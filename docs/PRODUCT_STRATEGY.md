# Toogeduler 제품 전략

최종 갱신: 2026-10-17 · 이 문서는 PM 에이전트가 우선순위를 정할 때 기준으로 삼는다. 바꾸려면 PR로.

## 한 줄
친구·동아리·팀이 각자 일정을 안전하게 공유하고, **모두가 되는 시간을 몇 번의 탭으로 찾아 바로 확정**하는 캘린더.

## 북극성 지표
**주간 확정된 그룹 일정 수** — "함께 되는 시간"에서 고른 시간이 실제 일정으로 확정된 횟수.
보조: 그룹당 초대 수락 인원, 가입 7일 후 재방문율, 유료 전환율(수익화 이후).

## 핵심 사용자
1. 대학 동아리·학회·스터디 운영진 (초기 타깃: 대학 커뮤니티)
2. 친구 모임 약속 잡는 사람
3. 소규모 팀(동아리 프로젝트, 스타트업)

## 단계
**2026-10-17 결정: 웹 먼저.** Apple Developer Program(연 $99)은 비용 때문에 미루고 `app.toogeduler.com`을 먼저 정식 출시한다. 스토어 앱(Capacitor)은 준비된 상태로 두고, 사용자와 여유가 생기면 Google Play($25) → App Store 순서로 낸다.

| 단계 | 목표 | 끝났다고 보는 기준 |
|---|---|---|
| 1. 웹 정식 출시 | 실사용자를 받아도 되는 품질·보안 | 아래 "1단계 남은 것" 완료 |
| 2. 초기 사용자 | 첫 100개 그룹 | 초대 → 가입 → 시간 찾기 → 확정 흐름이 끊김 없음, 웹 푸시 알림 |
| 3. 수익화 | 첫 유료 구독 | 요금제·결제·구독 상태 관리 동작. 웹 결제로 먼저 시작하면 스토어 수수료 없이 검증할 수 있다 |
| 4. 스토어 출시 | Google Play → App Store | `docs/APP_STORE.md` 체크리스트 완료 |

지금은 **1단계**. PM은 1단계 작업을 우선하되, 2단계 핵심 흐름(초대·확정·알림)의 마찰을 줄이는 작업을 섞는다.

### 1단계 남은 것

이미 끝남: 운영 DB 백업·복원 리허설(#25), Flyway(#17), 공개 범위 권한 테스트(SEC-010, PR #27), 휴대폰 로컬 알림(PR #29, 스토어 앱 빌드부터 적용), 초대 링크 미리보기·참여(PR #32), 운영 도메인·소셜 로그인 연결.

에이전트:
- 초대 링크 만료·재발급 (SEC-013, #21)
- PWA 설치·웹 푸시 알림 (EXT-003). 스토어 앱 없이 휴대폰 알림을 주는 방법
- 핵심 API 통합 테스트 (QA-001)

사람(고은):
- 노출 이력 있는 OAuth 시크릿 교체 (#26)
- Google·Kakao 실제 계정으로 로그인 확인 (AUTH-010/011)
- 스토어 출시 때: Apple 가입(#22, 보류), Google Play 계정·비공개 테스트(#23), 심사용 데모 계정(#24)

## 수익화 가설 (검증 전)
- **무료**: 개인 캘린더, 그룹 3개, 그룹당 10명, 기본 "함께 되는 시간"
- **Plus (월 구독)**: 그룹·인원 확대, 필수/선택 참석자, 개인별 가능 시간대 반영, 반복 일정 고급 편집, 외부 캘린더(Google/Apple) 동기화, 그룹 색상·테마
- **팀/동아리 플랜**(이후): 관리자 역할, 승인형 가입, 공지·출석
- 결제 경로: iOS/Android 앱 안의 디지털 구독은 각 스토어 인앱결제가 필요하다. RevenueCat 같은 구독 관리 도구로 iOS·Android·웹 구독 상태를 한 곳에서 관리하는 방안을 검토한다.
- 광고는 일정 데이터 신뢰를 해치므로 하지 않는다.

수익화 착수 전 필요한 것: 무료 한도를 강제할 사용량 측정, 요금제 상태를 저장할 백엔드 모델(엔티티 변경 → 사람 검토), 결제 연동 계정(사람이 준비).

## 하지 않을 것 (지금은)
- 채팅·메신저 기능
- 웹 전용 고급 기능 (모바일 앱이 주 채널)
- 대규모 리디자인
